# v3.0 数据说明

正式协议为四任务 × 四长度，每单元实验集 16 题、测试集 64 题，共 256/1024 题；另有每单元 4 题的 BF16 开发数据。定义见[设计文档](../../docs/v3.0/DESIGN.zh-CN.md)，操作见[离线运行手册](../../docs/v3.0/RUNBOOK.zh-CN.md)。

来源使用 [SQuAD 2.0](https://rajpurkar.github.io/SQuAD-explorer/) 的 train/dev 与 [HotpotQA](https://hotpotqa.github.io/) 的 train/dev distractor。两项来源均标注 CC BY-SA 4.0，归档保存作者、原始链接、许可链接及项目修改说明。HotpotQA 原站不可达时，准备脚本可从 [hotpotqa/hotpot_qa 镜像](https://huggingface.co/datasets/hotpotqa/hotpot_qa)读取完整分页并恢复原始 JSON 结构；若页面裁剪证据，先单题重取，仍不完整就报错，不把裁剪内容写进正式来源。

来源目录、生成数据和下载缓存不进入常规源码提交。运行器在实际输入副本中保存所用数据，结果导出时带回；不要把模型权重和整个原始语料库上传到结果目录。

| 目录 | 内容 |
|---|---|
| `source/` | 四份原始 JSON、来源清单与实际下载/导入信息；由联网 Linux 设备准备后传入 |
| `development/` | 独立开发题与数据清单，仅用于 BF16 难度、提示和输出预算分析 |
| `quality/` | `experiment.jsonl`、`test.jsonl`、数据清单；正式主流程读取 |

来源按规范化 Wikipedia 文档 ID 和相同文本合并，在生成题目之前分配 split。SQuAD 文档池单独平衡，以免被大背景池的抽样波动耗尽：来源文档约 10% 用于开发、18% 用于实验、其余用于测试；最终正式题数仍严格为 20%/80%。多跳题必须全部证据归于同一 split；每道题只使用一个长度，当前生成器每个 QA 证据组只取一题。

合成检索的自然背景和 QA 干扰背景也不跨 split。组内背景复用会记录，不把改变同一题的长度当成多个独立问题。原始公开 QA 可能出现在模型预训练中，本项目只保证自己选择流程与独立测试的边界，不声称消除了预训练污染。

`v3-make-data` 只执行本地文本处理和 tokenizer 计数，不启动 GPU 或下载模型。已有匹配数据会复用；任务、模板或输出预算改变后使用新数据版本。阈值和搜索预算属于运行协议，修改后会生成不同运行 ID，但不能把已用测试当成新的独立证据。

正式测试前自动写入 `test-use.json`。同一工作区中，改运行 ID 后重新使用旧问题或旧证据会在报告中标记为 `test_not_independent`，不算主目标达标。把文件复制到另一台机器无法证明其从未被使用，分析时仍须披露既有测试历史。
