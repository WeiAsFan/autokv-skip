# v4.0 数据说明

v4.0 用两个自行构造的短答案任务寻找 BF16 可解且全 FP8 有明显恢复需求的分布，然后执行自动选层与独立测试。任务、阈值与统计边界见[设计文档](../../docs/v4.0/DESIGN.zh-CN.md)，设备操作见[离线运行手册](../../docs/v4.0/RUNBOOK.zh-CN.md)。

`single_lookup` 使用双自然词键和唯一六位代码，至少一半干扰键与目标共享一个词。`two_hop_lookup` 使用独立案件→储物柜→代码映射，两条目标证据相距至少最终输入 token 数的三分之一。完整记录不可裁剪；仅背景随目标长度适配。生成器排除背景中的六位数字子串，防止目标代码在自然背景中意外出现。

默认网格为两任务 × `[8192,16384,24576]` tokens × `[16,64,128,256]` 条记录，每条件 64 个发现实例。双事实的记录量指案件数，并有等量储物柜映射。最多两个条件各用两批新的 512 题确认；每批均要求 BF16 正确率至少 `0.80`、BF16−FP8 严格超过 `0.10`，才能冻结一个正式生成规则。没有条件通过时保留负结果。

正式实验/测试分别生成新的 `512/4096` 题，只有所选的一个任务和长度。每题有自己的映射世界；换查询、记录顺序或背景不能将同一基础映射算作新的独立实例。六位代码采用二值评分：输出包含唯一正确代码即得 1，错误/空输出/多个不同代码得 0；重复正确代码不扣分但单独统计。

背景来源复用现有 [SQuAD 2.0](https://rajpurkar.github.io/SQuAD-explorer/) 与 [HotpotQA](https://hotpotqa.github.io/) 的原始包，来源准备和许可元数据沿用 [v3.0 来源说明](../v3.0/README.md)。来源记录中的作者、原始网址、CC BY-SA 4.0 许可与修改说明随运行归档保存。本文不把自定义任务成绩称为官方基准成绩。

文档按规范化 ID 和相同文本合并，按来源种类分别分入发现/确认/实验/测试四个池，比例约 `5%/5%/10%/80%`，小数余量给测试。同阶段背景可重复，跨阶段不借用；报告列出引用次数、不同文档数、复用比例和单文档最高使用题数。区间只解释固定背景池条件下的新映射分布，不能外推为全部长上下文任务的效果。

`source/` 是可选的本版离线来源目录，也可显式指定已有 v3.0 来源包。`v4-<id>/quality/` 是该轮正式数据的查看副本。两类大文件都不进入常规源码提交；归档包含实际使用的提示、映射、来源 ID、种子、位置和评分结果。续跑读取 `runs/<run_id>/inputs/` 与 `construction/` 中的实际输入，不因当前数据查看副本被改动而换题。
