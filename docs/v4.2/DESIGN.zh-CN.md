# v4.2 设计与实现说明

日期：2026-09-17。基于 v4.1 上传结果的提交 `c9b5353`，本版落实四项已确认的改动：直接复用数据、容量目标 2.0×、限制完整评估数量、发布精简分析包。

## 数据与成功标准

直接复制 v4.1 运行 `v41-40ef467cef6a32d2` 的正式 `experiment.jsonl`、`test.jsonl` 和 `dataset-manifest.json`。条件为 `single_lookup-l8192-r128`，512 条实验题和 4096 条未使用测试题；保留原文件字节、顺序、种子 `20260916`、背景、真值和划分。不会调用数据生成器、discovery 或 confirmation，也不需要原 SQuAD/Hotpot 来源库。

两批数据确认成绩作为 v4.1 历史证据保留，不计成本到新运行，不解释为新确认。新运行重新评估 P32、P0 和候选，不混用旧策略回答。首次导入后，续跑使用新运行内的输入副本，不依赖旧目录继续存在。自动输入身份用于防止混用缓存，不增加人工哈希步骤。

质量约束仍为总分下降不超过 0.01、每任务不超过 0.02；构造条件的 BF16≥0.80 和 BF16−FP4>0.10 不改变。主目标要求冻结候选在独立测试中通过质量约束，且实测 KV 容量至少为全 BF16 的 2.0 倍。点估计达标与非劣性统计证明分别表述。

FP4 沿用 v4.1 的 A6000 E2M1 软件解码实现，每 16 元素存一个 E4M3 scale，平均每元素 9/16 字节。保留 k 层 BF16 时理论倍率为 `64 / (2k + (32-k)*9/16)`；k=9 约 2.069×，k=10 约 1.977×，因此搜索最多到 9 层。最终采用测试服务的实际容量，不用理论值代替。

## 固定预算束搜索

`autokv/v42_search.py` 实现新调度；历史 v3/v4.0/v4.1 搜索规则不变。

1. 在完整实验集上评估 P32、P0。P32 无效时保留诊断；P0 满足最终质量约束时直接冻结端点，仍执行独立测试。
2. 束宽保持 2，从每条父路径增加任意一层 BF16，去重后对所有组合评估相同的前 32 题。
3. 每个深度最多 8 个组合补到前 128 题。第一层取前 8；之后每条父路径各取前 4，共享组合去重，空余名额按全局初筛排名补齐。并列由预先固定的随机顺序处理，不能额外扩大集合。
4. 依据相同 128 题上的质量排序选择下一轮两个父组合，不要求完整评估。排名沿用既有质量约束违背程度与分数；跨深度并列优先较少 BF16 层，然后按固定随机顺序。
5. 全程最多 6 个混合候选补到完整 512 题。搜索过程中最多使用 3 个，每个深度最多一个，优先确认本轮复筛已达到点阈值的最佳者。失败后继续搜索，完整评估分数不混入 128 题排序。
6. 搜索到容量允许的最大层数后，从历次复筛保留的候选中，按相同 128 题排名选择尚未完整评估者，依次用完剩余名额或找到合格配置。即使复筛无人达标，也执行末尾确认。早期未用名额全部转入末尾。
7. 找到完整实验集达标配置后立即冻结，不追加反向删层；P32/P0 与唯一冻结候选进入 4096 题独立测试。测试失败不换候选。没有找到时只报告预算内未找到，不声称不存在可行配置。

每个深度最多 8 个复筛、全程最多 6 个完整评估为硬上限；旧的“不确定或并列就额外晋级”不用于新调度。有限束宽和小样本排名会误淘汰候选，因此这是一项明确的计算预算取舍，不保证全局最优或必然找到可行解。

## 请求上界与恢复

初筛候选的保守上界为 `32 + 2*(31+30+...+24) = 472`。不重复请求已完成前缀时：

| 阶段 | 新请求上界 |
|---|---:|
| 初筛 | 472×32 = 15104 |
| 复筛 | 9×8×96 = 6912 |
| 完整确认 | 6×384 = 2304 |
| 搜索合计 | 24320 |

保留现有 24576 次搜索硬预算；包含实际重试及在途请求，所以异常较多时仍可能提前终止。端点基线最多 1024 次、最终测试最多 12288 次独立于搜索预算；完整正常运行最多 37632 次模型请求，不包括重试。构造阶段本次为零请求。

逐题缓存和固定决策使中断后重放同样的搜索路径，只补缺失回答，不增加第七个完整候选。最终选择写入 `selection.json` 后才开始测试；测试中断沿用该选择。既有测试已经使用过时标记为重跑诊断，不计独立测试达标。

四路请求并发不变。服务仍按配置与评估阶段重建，最多约 550 次搜索启动；深入搜索会增加短评估和加载次数，不承诺耗时按完整候选减少比例下降。记录实际请求、重试、启动、耗时和完成深度，用于区分预算完成与技术目标达标。

## 精简发布与运行环境

`scripts.export_v42_results` 生成中文报告和每个运行一个 `evidence.zip`。ZIP 只收集分析所需内容：

- `samples.jsonl`：正式样本 ID、原顺序索引、分层与来源组、真值、长度和证据位置，不含长提示与 world。
- `answers.jsonl`：全部已完成的逐题短回答、原分数、策略 ID、输出结束原因、token、延迟、重试与时间。
- `attempts.jsonl`：各次服务的策略、实际命令、容量、dtype 检查、请求与耗时、完成/错误状态；请求 ID 数组改为计数，回答仍可用 attempt 字段关联。
- 原始搜索决策、请求错误、运行/完成清单、冻结选择、精确运行代码、配置、环境和 FP4 适配差异。
- 每次服务日志首尾摘要、CLI 日志首尾摘要，及损坏行的导出位置说明。

可据此重新评分、做样本配对、检查选层与预算、汇总真实容量和成本。不能仅靠分析包恢复完整长提示或所有故障现场；这些保留在服务器原始运行目录。导出允许失败、未完成及只有 CLI 日志的情况，不修改损坏源文件，不把坏行当作成功样本，也不生成原始 tar 归档或分片。

本版沿用 v4.1 已成功执行的隔离运行环境，将上传源码中已有的 TVM-FFI 兼容路径、依赖优先级和可配置编译缓存路径纳入运行器，避免新目录丢失已修好的部署设置。不修改 FP4 量化格式、attention 算法或模型权重。

服务器有 Git 但不能联网或推送；Linux 登录设备可联网但不能推送。源码离线传入，精简结果经 SCP 回传 Linux，在 GitHub 网页选择 v4.2 手动提交。无需 doctor、smoke、预先提交或人工核验哈希。实际步骤见[运行手册](RUNBOOK.zh-CN.md)。
