# v4.1：A6000 FP4 KV 实验

本版将低精度端点从 FP8 改为 FP4，保持 v4.0 的数据生成和 v3.0 的束搜索。目的仍是自动选择 BF16 KV 层，在质量容差内提高实测 KV 容量。FP4 不保证一定产生足够质量缺口，也不保证少量 BF16 层能够恢复。

## 格式和硬件路径

KV 使用 E2M1：绝对值码本为 `0, 0.5, 1, 1.5, 2, 3, 4, 6`，另有符号位；相邻两个值打包为一个字节。每个 token、每个 KV head、每 16 个元素有独立 E4M3 scale。先计算 `amax/6`，舍入为实际存储的 E4M3 值，再用它量化 E2M1，边界采用最近偶数舍入。K/V 分别计算，当前全局因子为 1。全零/极小分组将 scale 下限设为 `2^-9`，scale 上限为 448；这意味着全局因子 1 时组内绝对值超过 2688 会饱和，需在出现异常时检查实际 KV 范围。

这里的动态分组 scale 与 vLLM 的 `--calculate-kv-scales` 不同：前者随每组数据保存并由读取内核解码，后者只在首次 forward 估计整层全局 scale。本版关闭后者，不能把 FP8 的“所有值共用 scale=1”直接搬给 FP4。

A6000 是 SM86，没有原生 FP4 Tensor Core。写入使用普通 PyTorch CUDA 运算，持久 KV 是实际压缩的 `uint8` 数据和 scale；FlashInfer FA2 在片上将历史 KV 分块展开后执行 BF16 attention。没有保留一份完整 BF16 历史缓存。Q、输出及权重保持 BF16，所有策略使用 eager，避免把输出 FP8 量化或不同执行方式混入 KV 精度比较。

FlashInfer [PR #4769](https://github.com/flashinfer-ai/flashinfer/pull/4769) 已提供 pre-SM100 的软件展开路径并报告 SM80 测试；本版选用合并提交 `a4c17d77a15fbff1ef7b34a4ad2b5faaa5bdd6dc`。SM80 证据支持尝试 SM86，但不是本项目在 A6000、CUDA 12.9 上实测通过的证据。

既有 [vLLM c18d29d36 后端](https://github.com/vllm-project/vllm/blob/c18d29d36/vllm/v1/attention/backends/flashinfer.py) 的 NVFP4 路由仅面向 SM100。`autokv/fp4_runtime.py` 在独立包副本中接入 SM86 FA2、BF16 Q/O 与项目写入器，保留现有分页分配及逐层 skip 机制。匹配补丁所需的接口片段是为防止改错版本，不要求操作者核对哈希。旧环境不改动，旧版 JIT/AOT 二进制也不复用。

首版限制为单卡 A6000、HND、head_dim 为 16 的倍数、现有 Mistral 7B、eager；不新增模型权重量化、分布式或吞吐优化。PyTorch 写入可能较慢，应记录墙钟成本。该实现不能提前宣称吞吐提高。

## 容量和搜索

每个低精度 KV 元素占 `0.5 + 1/16 = 9/16` 字节。32 层中保留 k 层时，相对全 BF16 的理想容量倍率为：

```text
R(k) = 64 / (2k + (32-k) × 9/16)
```

全 FP4 上限为 `32/9 ≈ 3.5556×`；1.5 倍容量目标最多允许保留 17 层。实际分页分配、混合组布局和工作空间仍可能改变可用容量，主实验使用引擎报告的 KV token capacity，不把理论值当作实测值。

发现每条件 64 题；选择最多两个条件，各用两批全新 512 题确认。每批要求 BF16 ≥ 0.80 且 BF16−FP4 严格 > 0.10。通过后冻结规则，生成 512 题实验集和 4096 题测试集。正式搜索保持束宽 2、32/96/512 多保真评估、24576 请求预算；最终质量容差保持总分 0.01、任务 0.02。数据种子改为 20260916，避免直接复用旧版实例。

P0 在新实验集已达标时仍可早停。构造失败、搜索预算用尽、独立测试失败都应如实保留，不自动调阈值、重抽题或改精度。

## 实现和验证状态

已实现格式编码、实际分页写入、SM86 后端适配、精度参数在完整流程中的传递、含 scale 的容量预算、FP4 统计字段和隔离环境/导出命令。历史 FP8 配置与报告保持可读；v4.1 的 CLI 默认配置为 `configs/v4.1/quality.json`。

CPU 测试覆盖码本、舍入、非 1 scale、零值、分页偏移和端到端模拟；模拟不代替 GPU 结果。可选 `scripts/check_v41_fp4.py` 在服务器比较真实 FA2 的 prefill/decode 与解码参考 attention。当前工作区没有 A6000，尚未验证新 FlashInfer 的 CUDA 12.9 JIT 编译、完整模型启动、混合精度缓存及质量/容量实测。

## 请求并发优化

当前配置默认保持 4 个在途请求，使同一 vLLM 服务有机会批处理多个样本；各精度和各阶段使用同一上限。工作线程只发送 HTTP 请求，主线程负责预算计数、重试决策、响应校验与结果写入。每次派发前计入请求预算，最多重试一次暂时性错误；错误或预算耗尽后停止派发，并收集已发出的请求。返回结果恢复为所请求的样本顺序，缓存文件允许按完成顺序记录。

并发数进入运行配置和每次 attempt 记录，未设置该参数的历史配置保持串行。这个改动没有减少样本数、放宽阈值或修改 FP4 内核；实际耗时改善尚需 A6000 实测。
