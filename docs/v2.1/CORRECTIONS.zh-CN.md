# AutoKV-Skip v2.1 修正说明

基于：`v2.0` 的 `2280edc`。本版落实已确认的五项修正，技术主目标是：在固定模型、运行时和任务数据下，自动选择 BF16 KV 层集合，其余层使用 FP8 KV；在独立留出集上满足质量下降阈值，并在相同 KV 显存预算下取得明显容量收益。模型权重精度保持原样。

## 1. 明确主验收条件

- 总分 `S_v2` 是 Easy、Hard、Natural 三类任务均分的等权平均，沿用 v2.0 定义。
- 相对 `P32`，总分下降不超过 `0.01`，Hard、Natural 各下降不超过 `0.02`。这些是归一化分数的绝对差值。
- BF16 基础题必须全部通过；候选也必须通过全部基础题。
- 在相同 `16G` KV 显存预算下，最终策略的实测 token capacity 至少为 BF16 的 `1.5×`。
- `complete` 只表示流程已得出结果；`technical_goal_passed` 才表示质量与实测容量同时达标。安全回退 `P32` 不算达成容量目标。
- 全 FP8 达标时允许输出 `P0`。真实容量缺失时保留质量结果，将容量标为未验证，不能用理论值替代。

## 2. 修正任务评分与基线判定

继续使用 45 条数据、27 条 calibration 与 18 条 held-out。Easy、多键检索、聚合和自然 QA 的任务结构保持不变。

变量追踪要求输出 `VAR-00=VALV-XXXXXXXX` 形式的变量与值，按正确配对的 F1 评分。重复值保留在各变量名下；缺少变量、交换变量对应值、输出冲突值都不能获得满分。生成复制赋值时保持四个查询变量至少有两种值，避免整道题退化为重复同一个答案。该规则只依赖任务结构，不查看模型输出。

正式 BF16 结果直接用于基础题判定。基础题失效时保存原始结果和报告，输出 `invalid_reference`，不继续无意义的搜索；不为此增加 smoke 或额外 GPU 启动。

新配置位于 `configs/v2.1/quality.json`，新数据位于 `data/v2.1/quality/`，评分版本为 `autokv-v2.1-score-v1`。保留 `data/v2/quality/` 的历史数据。首次运行使用服务器现有 tokenizer 离线生成新合成题，并复用旧数据中已经选定的 12 条自然 QA，保持其 split 和答案；无需重新下载 LongBench。已有新数据时直接复用。

## 3. 保留已验证的候选，减少重复实验

先运行 calibration 的 `P32/P0`；仅在 P0 未达标时运行八个四层组和前两组的八个单层探测。所有已评估、质量达标的单层和组配置都保留为候选，允许输出 `P1`。

单层没有合格配置时，按固定排序尝试嵌套 `P2/P4/P8`。已存在合格四层组时，不因新组合失败而退到八层；相同层集合按 `config_id` 复用同一 split 的结果。选择已评估合格候选中 BF16 层数最少者，同预算依次按总分高、层号小打破并列。该搜索不声称全局最优。

候选确定后只进行一次 held-out 验证，不根据 held-out 重新排序或改预算。失败时回退 BF16，并明确本次技术目标未达成。

## 4. 报告直接回答质量与容量目标

主实验只运行 BF16、全 FP8 和去重后的候选的 held-out 质量。报告给出各类及逐任务绝对分数、配对分差、95% bootstrap 区间、阈值判定、理论容量和实测容量倍率。

固定留出集的实际分差用于工程验收，置信区间用于说明不确定性，不增加统计门禁。45 个样本的结论限定在本数据及运行环境中。

三组同预算随机对照改为主实验完成后的可选命令，单独保存结果与配对分析。随机对照不影响主实验验收，不从随机结果中挑选部署配置，也不把“高于中位数”自动写成“层排序有效”。

## 5. 轻量运行与离线交付

沿用现有 vLLM、模型和可选环境锁。固定 KV scale 路径和关闭 prefix caching 的设置，保留实际 dtype、prompt token、输入一致性和原始结果完整性检查。没有新的 doctor、smoke、Git 提交/推送前置要求或人工哈希步骤。

小型服务器有 Git，但无法访问外网或推送 GitHub；Linux 登录设备能访问外网，但也不能推送。源码通过 Linux 设备下载并传入服务器，结果及失败日志从服务器回传 Linux 设备，再从 GitHub 网页上传并手动提交到 `v2.1`。当前开发工作区按用户授权负责代码提交与推送。

吞吐、TTFT、TPOT/ITL 属于后续性能扩展，不阻挡质量与容量主实验。运行手册见 [v2.1 离线运行手册](RUNBOOK.zh-CN.md)。

开发验证覆盖全零基线、变量映射评分、已通过组配置的保留、P1、候选去重、留出集失败、容量不足或缺失、可选随机分析，以及离线数据生成与归档。真实 GPU 质量、容量和性能必须在目标服务器测量，开发测试不作为 GPU 结果。
